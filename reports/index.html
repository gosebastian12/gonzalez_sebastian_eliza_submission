SEC EDGAR filings summary

Corpus inputs & filing headers

Ingestion assumes plain-text exports matching *_full.txt; logic lives in src/backend/data_processing/chunk_and_embed.py.

  • Preface strip: if SEC_REPORT_START_RE matches “UNITED STATES SECURITIES AND EXCHANGE COMMISSION”, body chunking starts there via strip_preface_noise; otherwise the whole file is used.
  • Header metadata: first lines before === are scanned with keys mapped to company, ticker, filing_type, filing_date, report_period, quarter, cik, source. Missing ticker/type fall back to parsing the filename pattern ticker_form_quarter_filingdate_*.
  • form_type: copied from filing_type for downstream metadata (matches stored ingestion strings such as “10-K (Annual Report)” / “10-Q (Quarterly Report)” — see extract_header_metadata).
  • SYSTEM_PROMPT in rag_prompts.py tells the model context comes from 10-Q and 10-K filing text (wording as defined in that constant).

Default corpus dir: DEFAULT_CORPUS_DIR = repo root / edgar_corpus (resolved via Path.parents from chunk_and_embed.py); override with --corpus-dir.

System architecture

Runtime architecture

Browser submits POST /chat; FastAPI runs EdgarHybridRAG.answer inside run_in_threadpool.

  • Module load: main.py resolves llm-user-prompt.py and imports via importlib; inserts services dir on sys.path.
  • Config reload: fingerprint from dataclasses.asdict(RAGConfig.from_env()); new EdgarHybridRAG when fingerprint changes.
  • Services: LangChain Chroma with host/port + collection; OllamaEmbeddings + ChatOllama with num_predict, num_ctx, timeouts.

Source: src/frontend/main.py, src/backend/services/edgar_hybrid_rag.py, src/backend/services/llm-user-prompt.py

Chunking, embedding & ingestion

Multi-stage chunking pipeline

build_documents_for_report() builds LangChain Document rows before embedding.

  • Sections: split_into_sections splits on HEADING_RE (PART / ITEM lines).
  • Tables vs prose: split_tables_and_text tags blocks as table or text using pipe/heuristic line detection.
  • Text grouping: split_semantic_text groups paragraphs; subheadings from SUBHEADING_RE start new units.
  • Length cap: split_with_overlap enforces max_chars / overlap_chars (CLI defaults 800 / 100).
  • Ingest: ingest_documents batches embeddings through Ollama and Chroma.add_documents; optional skip by deterministic chunk id.

Source: src/backend/data_processing/chunk_and_embed.py

Retrieval & reranking

Hybrid retrieval then reorder

  • Where clause: build_chroma_where_clause merges regex-derived filters (form, quarter, ISO date) with tickers from extract_tickers_for_retrieval (name map + filtered TICKER_RE). Multiple tickers become $or; form_type_metadata_clause expands normalized 10-K / 10-Q to stored variants.
  • Multi-company: when len(extract_tickers_for_retrieval) >= 2, each ticker runs similarity_search_by_vector with build_chroma_where_clause_for_ticker and per-ticker k derived from semantic_k and multi_entity_per_ticker_semantic_k; pools merge then dedupe.
  • Fallback: empty filtered search retries with combined chroma_where, then unfiltered search if still empty.
  • Dedupe key: file_name :: chunk_index :: section_title (document_identity_key).
  • Rerank: rerank_lexical_then_recency sorts by substantive flag, keyword/metadata score, log1p(length)*length_log_weight, then recency unless query_pins_specific_period or disable_recency_boost.
  • Optional LLM rerank: if use_reranker, rerank_with_llm scores first rerank_top_n docs using snippet [:1500] chars and JSON score parse.
  • Return slice: reranked[:final_k].

Source: edgar_hybrid_rag.py, edgar_query_patterns.py, rag_reranking.py, rag_config.py

Generation & UI

Prompt assembly & chat UI

  • System: SYSTEM_PROMPT constant from rag_prompts.py (exact wording including filing/tabular guidance as in source).
  • Human template: ChatPromptTemplate.from_messages in answer() inserts user question plus build_retrieval_context(...) output with fixed instruction strings after context.
  • Context budget: effective_context_char_budget derives a hard character cap from num_ctx, num_predict, overhead estimate; max_context_chars also clamps. Builder concatenates chunk headers (ticker, form, file, section, …) and bodies; truncates per chunk when needed with continuation per implementation.
  • API payload: answer, sources, source_chunks, metadata_filters_used, retrieval_where_clause, retrieved_count, sources_count, period_pinned_in_query.
  • UI: chat.html renders message.content without length truncation; Sources list when source_chunks is defined post-success. Timeout via RAG_HTTP_TIMEOUT + asyncio.wait_for.

Source: rag_prompts.py, edgar_hybrid_rag.py, rag_context.py, src/frontend/templates/chat.html, main.py

Testing approach

How runs are configured & exercised

  • Web UI: manual prompts through FastAPI form POST to /chat; same path calls rag.answer.
  • Environment knobs: RAGConfig.from_env() reads variables documented in rag_config.py (e.g. RAG_SEMANTIC_K, RAG_FINAL_K, RAG_MULTI_ENTITY_PER_TICKER_SEMANTIC_K, RAG_USE_RERANKER, RAG_NUM_PREDICT, RAG_NUM_CTX, collection/host/port, models).
  • CLI: llm-user-prompt.py exposes --query, collection/chroma flags, --semantic-k, --final-k, --use-reranker merged via dataclasses.replace(RAGConfig.from_env(), …).
  • Optional dotenv: main.py calls load_dotenv() when python-dotenv is installed.

Automated test harness not present under src/ for this deck; manual/Q&A prompts tracked separately by maintainers.

Findings

Behavior encoded in source (selected)

Listed items are direct consequences of implemented branches—not benchmark scores.

  • Issuer coverage control: multi-ticker questions trigger isolated filtered searches per symbol before pooling (addresses embedding dominance in a union).
  • Graceful degradation: metadata-only filters that yield zero hits fall back to wider then unfiltered vector queries.
  • Ticker hygiene: single-letter TICKER_RE matches excluded from extract_metadata_filters (len(t)>=2); shared FALSE_TICKER_WORDS filters noisy uppercase tokens.
  • Query normalization: normalize_query_text (NFKC + curly apostrophe flattening) feeds alias resolution and rerank keyword alignment.
  • Chunk sourcing: UI attaches source_chunks mirroring retrieved docs; empty retrieval surfaces explicit Sources placeholder copy in template.

Maps to edgar_hybrid_rag.py, edgar_query_patterns.py, rag_reranking.py, chat.html, main.py

Limitations & future improvements

Limits enforced by current code

  • Generation length: Ollama num_predict caps completion tokens; answers truncate when budget exhausted mid-stream.
  • Context window math: RAGConfig.normalized() clamps num_predict vs overhead/token slack assumptions documented in that method.
  • Retrieval breadth: candidate pool bounded by semantic_k / per-ticker analogues; final list capped by final_k.
  • LLM rerank scope: scoring invoked only for prefix length rerank_top_n; tail retains lexical order.
  • Infrastructure coupling: runtime depends on reachable Chroma HTTP API and Ollama models configured via env defaults in RAGConfig.
  • SYSTEM_PROMPT body: trailing separator snippet exists verbatim inside rag_prompts.py constant—review if unintended for production prompts.

Future work is out of scope for this deck unless merged into src/
